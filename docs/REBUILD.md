# Новая реализация 3D Room

Дата начала: 22 ноября 2026 года. Основание — текущая просьба пользователя создать весь код с нуля и разместить работу в `SHAN120186/3D_Room`, затем создать сайт.

## Какие решения действуют

Три исходных документа сохранены в `docs/reference/` вместе с историческим журналом. Журнал описывает другой компьютер и отсутствующий исходный код. Результаты его тестов, снимки и отметки `[x]` не перенесены в статус новой реализации.

| Решение | Применение в новом репозитории |
|---|---|
| D-01–D-18 | Предметные требования сохраняются: прямоугольные комнаты, общая квартира, сантиметры, пустой старт, отделка, свет, прогулка, история |
| D-19: прежние паузы после каждого этапа | Текущая просьба создать весь проект разрешает последовательную реализацию и проверку без повторных вопросов по уже решённому объёму |
| D-20: прежний локальный путь и агент | Рабочий проект — переданный пользователем репозиторий `SHAN120186/3D_Room` |
| Стек | React, TypeScript, Vite, Three.js/R3F, SVG; версии фиксируются lock-файлом новой установки |
| Модели | 35 оригинальных параметрических изделий; FurniMesh не включён |
| Обои | Проверенная тканевая текстура Rough Linen от Poly Haven, CC0-1.0 |
| Хранение | Состояние текущей вкладки; аккаунты и сохранение между сессиями не добавлены |
| Публикация | Пользователь попросил создать сайт; фактический адрес сообщается только после успешного деплоя |

Ссылка на репозиторий не доказывает возможность записи в него: успешный push и успешный деплой проверяются отдельно.

## Принципы реализации

- Проект хранит геометрию в сантиметрах. Сцена использует метры после одного преобразования на границе отображения.
- Общая стена и её дверной проём существуют в одном экземпляре. Стороны стены имеют независимую отделку.
- Чистовые контуры и площади вычисляются из стен, а не редактируются как отдельная копия данных.
- Изменение сначала строит кандидат. После общей проверки применяются все последствия либо не применяется ничего.
- Предпросмотр, камера, активная комната и время суток не добавляются в историю проекта.
- Ошибка размещения содержит текстовую причину; красный цвет дополняет сообщение.
- Каталог описывает типовые изделия, а не товары известных производителей. Источник размеров — собственный параметрический проект; размеры не выдаются за замер чужого товара.

## Уточнения исходных документов

В исходных файлах нет координат девяти схем. Новые схемы восстанавливаются по согласованному составу помещений, а площадь всегда рассчитывается из фактической геометрии. Старые значения площади не используются как фиктивные подписи поверх другой геометрии. Уже увеличенные размеры не увеличиваются повторно на 21%.

Фраза PRD о «зонах пользования мебелью» не добавляет неизвестных расстояний: SPEC D-06 требует проверки дверного проёма и открывания створки, но не ширины проходов. Установка на поверхность мебели ограничена настольной лампой и явно заданными опорами.

Прежний эталонный кадр `docs/stage-4/01-overview.png` не предоставлен. Сравнение с ним не объявляется выполненным. Браузерный path tracing должен рендерить ту же геометрию; нейросетевое изображение не используется как доказательство точной планировки.

## Передача результата

Фактическая реализация, команды проверок, ограничения окружения и незавершённые критерии записываются в [VALIDATION.md](VALIDATION.md). Старые этапы остаются исторической справкой, пока новые проверки не подтверждают соответствующие свойства.
